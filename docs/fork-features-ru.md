# VibeBar: от лаконичной идеи к модульной системе

В основе проекта — гениальная по своей лаконичности идея Маргулана Сейсембая: минимум действий, максимум пользы. Нажал горячую клавишу, назвал текущее занятие — и журнал рабочего дня складывается сам.

Оригинальный VibeBar для macOS объединяет четыре инструмента: голосовой трекер одной текущей задачи, отдельные записи идей, напоминания и менеджер последних 15 фрагментов буфера обмена. Он рассчитывает время по промежуткам между записями, строит дневной и недельный отчёты и умеет переносить их в Obsidian. Исходная голосовая цепочка работает через Superwhisper и macrowhisper, а меню — через SwiftBar.

Эта версия сохраняет исходную модель, формат Markdown-журнала и оригинальные скрипты, но добавляет следующие возможности.

## Что добавлено

1. **Полноценная версия для Windows.** Отдельное настольное окно, системный трей, запуск вместе с системой, скрытие и восстановление окна без всплывающих окон консоли.
2. **Единая логика для Windows и macOS.** Задачи, идеи, напоминания, перерывы, буфер обмена, дневные и недельные отчёты используют общую бизнес-логику и тот же формат журнала.
3. **Три языка интерфейса и команд:** русский, английский и иврит. Язык переключается из интерфейса, а переводы вынесены в независимые JSON-каталоги — новый язык можно добавить без изменения кода интерфейса.
4. **Многоязычное распознавание типа записи.** Слова для задачи, идеи, напоминания и перерыва собраны в отдельном заменяемом словаре.
5. **Собственные голосовые команды.** Пользователь может добавить свою фразу — например, «обед» — и назначить ей тип: задача, идея, напоминание или перерыв. Команды можно просматривать и удалять.
6. **Полностью локальная фраза активации Hey Computer.** openWakeWord слушает только акустический признак ключевой фразы на самом компьютере; после срабатывания запускается запись команды.
7. **Локальное распознавание через whisper.cpp.** Поддерживается существующий C++-движок Whisper Large-v3-Turbo/Vulkan; звук не требуется отправлять в облако.
8. **Сохранён оригинальный голосовой маршрут macOS.** Superwhisper + macrowhisper остаётся вариантом по умолчанию на Mac; локальный openWakeWord + whisper.cpp подключается как альтернативный модуль, голос можно отключить.
9. **Глобальная горячая клавиша на Windows:** `Ctrl+Alt+Space`. Она запускает ту же запись, не требуя открывать окно программы.
10. **Звуковые сигналы начала записи.** Реализованы отдельными платформенными адаптерами и не блокируют захват микрофона.
11. **Адаптивное окончание записи.** Система сначала измеряет фоновый шум, ждёт настоящего начала речи и завершает запись только после тишины после речи. Она не обрывает команду по фиксированным двум секундам и не задерживает готовый текст на 30 секунд.
12. **Диагностика всей голосовой цепочки.** Отдельные состояния и журнал позволяют различить ожидание ключевой фразы, запись, транскрипцию и сохранение, вместо догадок о месте сбоя.
13. **Раздел «Что я сделал».** Результат или достижение можно продиктовать отдельно; запись появляется немедленно, помечается `✅` и не останавливает текущую задачу.
14. **Постфактум-категории задач.** После рабочего дня задаче можно назначить постоянный номер категории, даже если Whisper неточно распознал её формулировку.
15. **Настраиваемые категории.** По умолчанию доступны письмо, учёба, звонки, управление и отдых; названия отображаются на выбранном языке.
16. **Итоги по категориям.** Добавлены дневная и недельная агрегации времени по постоянным категориям.
17. **Живой таймер без опроса файлов каждые три секунды.** Интерфейс читает запись при событии, а затем обновляет только локальное отображение времени каждую секунду.
18. **Отдельная вкладка перерывов.** В журнале и интерфейсе явно показаны время начала перерыва и его запись в общей хронологии дня.
19. **Автоматическое определение ухода по Bluetooth.** Выбранные наушники или другое Bluetooth-устройство могут служить личным маркером присутствия.
20. **Выбор устройства-маркера из интерфейса.** Можно обновить список известных устройств и назначить нужное, не меняя код или конфигурационный файл вручную.
21. **Оценка удаления по живому RSSI.** Для Windows Classic Bluetooth создан отдельный нативный считыватель; для macOS предусмотрен адаптер к `IOBluetoothDevice.rawRSSI()`.
22. **Устойчивое решение вместо реакции на один замер.** Используются медиана, разные пороги ухода и возвращения и несколько последовательных подтверждений.
23. **Пятиминутное правило перерыва.** Если пользователь вернулся раньше пяти минут, журнал не меняется. Если отсутствие длилось дольше, перерыв записывается задним числом с настоящего времени ухода.
24. **То же правило при полном отключении Bluetooth.** Отключение не создаёт мгновенный ложный перерыв; оно проходит через тот же пятиминутный шлюз.
25. **Безопасная обработка неизвестного состояния.** Отсутствующий или ошибочный сигнал RSSI не считается уходом и не способен самостоятельно изменить журнал.
26. **Автоматическое восстановление Bluetooth-считывателя.** Если нативный процесс замолчал или завершился, контроллер перезапускает его с ограниченной задержкой; защита единственного экземпляра не допускает нескольких конкурирующих мониторов.
27. **Выборочное наблюдение за буфером обмена.** Автоматический монитор можно включить и выключить; по умолчанию он выключен, поскольку скопированный текст может содержать секреты.
28. **Полное управление буфером на Windows:** захват текущего текста, просмотр, копирование, удаление одной записи и безопасное подтверждение очистки.
29. **Событийное обновление интерфейса.** Новые голосовые записи и подтверждённые перерывы отображаются после сохранения, без ожидания старого периодического обновления.
30. **Изолированный демонстрационный журнал.** Для скриншотов можно указать отдельный файл и не показывать личные записи пользователя.

## Что изменено внутри

31. **Модульная архитектура без переписывания оригинала.** Принцип проекта: «существующее не заменять; модульность — это обернуть в разъём». Оригинальные скрипты остаются источником истины.
32. **Контракт, реальный адаптер и безопасная заглушка для каждого внешнего сервиса.** Если модуль не подключён, заглушка не удаляет, не публикует, не вставляет и не перезаписывает данные.
33. **Единая точка сборки зависимостей.** Выбор реального или пустого адаптера сосредоточен в слое сборки, а не разбросан по интерфейсу.
34. **Композиции возможностей.** Наборы `pilot`, `windows`, `macos` и `full` определяют, какие действия действительно подключены; интерфейс показывает только подключённые функции.
35. **Независимые платформенные адаптеры.** Windows-код не импортирует macOS-код и наоборот; общая логика находится в отдельном слое.
36. **Bluetooth и учёт отсутствия оформлены как самостоятельные блоки.** Источник сигнала, фильтр RSSI, пятиминутное правило и запись в журнал можно заменять и тестировать по отдельности.
37. **Заменяемая граница речи.** Алгоритм окончания записи подключён через контракт и может быть заменён без изменения контроллера голоса.
38. **Заменяемые часы.** Бизнес-логика получает время через отдельный Clock, благодаря чему переход даты и расчёты можно проверять детерминированно.
39. **Ограничения качества кода.** Для нового модульного слоя проверяются пределы размера файлов и функций, типизированные интерфейсы, отсутствие голых `except Exception`, прямых `print()` и прямого системного времени вне Clock.
40. **Автоматические кроссплатформенные проверки.** Тесты покрывают модульные контракты, команды, категории, таймер, голос, Bluetooth, Windows-интерфейс и macOS-адаптеры; GitHub Actions предусматривает проверку macOS на настоящем runner.

## Важное уточнение

Базовая идея, исходный формат журнала, расчёт времени, четыре исходных инструмента и первоначальная интеграция macOS принадлежат оригинальному проекту Маргулана Сейсембая. Перечисленное выше — расширения этого форка. Программная совместимость macOS проверяется автоматически, но микрофон, системные разрешения и физический Bluetooth всё равно требуют окончательной проверки на реальном Mac.
